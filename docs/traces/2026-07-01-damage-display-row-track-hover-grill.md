# 伤害对比结果显示：行标识 / 数轴 / hover 讨论记录

对应 issue: [[20260626_open_damage-comparison-results-info-display-needs-refinement|Results info display]]（归档后的原型迭代，三轮：row-identity / track-display / hover-style）

## 1. 行标识布局

问题：「招式 xx vs xx」行标识怎么排？现有右对齐文字列信息密度低、标识与图的对应关系不直观；卡片若上下堆叠（标识在上、图在下）又拉长纵向占用。

决定：左侧 `w-60` 带边框卡片，纵向「标签: 值」三行（招式 / 攻击 / 防御），道具图标内联在「攻击」行、无加成时附「无加成」；右侧箱线图占满剩余宽度。标识与图保持左右关系（同「现状」），不上下堆叠。

## 2. 百分比数轴与实数值

问题：数轴是否保留、是否冻结？伤害实数值是否显示？

决定：保留百分比数轴，`sticky top-0`（Excel 冻结顶行），刻度起点与左侧卡片宽 + gap 对齐；不显示伤害实数值，track 底部仅保留百分比区间 + 暴击区间 + OHKO。

## 3. 默认标签密度

问题：track 底部默认标签（通常区间 / 暴击区间 / OHKO）太多，如何压缩？

决定：内联只留「通常区间 + OHKO」；暴击区间、平均移入 hover，不在内联默认展示。

## 4. 超出 100% 的展示

问题：>100% 的伤害在线性 0–150 轴上被 clamp 到边缘、暴击 182% 的端点贴边不可读，样式糟糕，如何展示？

决定：非线性轴——0–100% 线性占轴 72% 宽，100–200% 用 `sqrt` 压缩进剩 28%，100% 处虚线 scale-break 标示刻度切换，硬上限 200%（再大 clamp 到右边缘）。轴上限 200% 对当前数据（暴击峰值 182%）留有余量。

## 5. hover 样式

问题：移入 hover 的信息用什么样式呈现？原生 `title` 出现慢、样式不可控；自绘卡片会挡住箱形图。

决定：用 shadcn `Tooltip`（base-ui `Positioner`）承载行级合并卡片。trigger = 整条 track（hover 任意位置即弹），content = 通常 / 平均 / 暴击 / OHKO 四行，配色对应 track（通常色点、平均竖线、暴击紫点、OHKO 红）。定位 `side="top"` `sideOffset={8}` `align="center"`，依赖 base-ui 碰撞检测 + 自动翻转，上方空间不足时翻到下方，不压住箱形图或冻结轴；`TooltipProvider` 包在 App 根，`delay=0` 即时弹出。

## 6. 配色与视觉细节

问题：hover 卡片的配色、字色对比、箭头、对齐等视觉细节是否在本轮定？

决定：不在本轮定，**留给实现阶段自行决策**；本轮只锁定结构与交互（shadcn Tooltip + 行级合并卡片 + 碰撞翻转）。
