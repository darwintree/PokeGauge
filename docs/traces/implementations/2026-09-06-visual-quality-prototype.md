## Entries

### 1. 独立原型与视觉方向

Type: unresolved-implementation-decision

Context:
用户未指定布局候选、交互深度或示例数据。prototype 技能偏好现有路由，但用户明确要求纯 HTML。

Decision:
在 Scenario Explorer 邻近位置建立独立、自包含 HTML；提供轻量 HUD、横向工作台和双栏报告三个布局，以轻量 HUD 为默认。采用内存中的展示数据，注明不接入计算引擎。尝试正文与数字分字体、柔和面板阴影、减少粗边框；保留浅色和领域色分工。不更改生产页面及设计规范。

Reason:
可离线直接打开，并用相同内容比较不同信息密度；纯新增、可丢弃原型没有现有消费者兼容负担。

Follow-up:
待用户评估方向后再决定正式实现与规范修订。

### 2. 将比较范围收敛到设计细节

Type: interpretation

Context:
用户明确指出当前应主要考虑质感细节，而非大框架。上一轮三种布局分散了评价重点。

Decision:
删除布局切换，固定上一轮 A 的结构。加入面板、字体、控件、数据标记、线条五个独立视觉开关及上一版样式对比；明确上一版是 HTML 基线，非生产页面。只对样式进行实验，不继续探索信息结构。

Reason:
同一内容与布局下的独立开关能让用户判断每项细节的收益。原型尚未被正式实现依赖，可以直接移除布局候选。

Follow-up:
由用户评估细节方向。

### 3. 改用当前产品组件作局部对照

Type: interpretation

Context:
用户进一步明确要求与当前产品方案对比，说明质感提升点。

Decision:
移除上一版页面与细节开关方案，改为四组并排局部样本。当前一侧抽取本工作区实际 CSS（面板、TrackOption、Stat Value Label、伤害条）；右侧逐项调描边、阴影和内侧亮边。明确标注代码抽样、样本尺寸约束和来源，不声称是线上截图。首组仅改面板，保留内部按钮一致，以隔离变量。

Reason:
用当前组件而非新布局作基线，才能把收益归因到具体设计细节。保留黄色信号、硬阴影语言与伤害域渐变，避免把改变风格当作提升质感。

Follow-up:
待用户评估局部对照。

### 4. 将批准的细节应用到生产组件

Type: unresolved-implementation-decision

Context:
用户批准四项局部调整，样本未覆盖结果主面板、紧凑能力值标签及特殊选项修饰符。现有产品已供用户使用，按稳定表面保留布局、信息与交互语义。

Decision:
设置面板与结果主面板共用较轻的 HUD 边框，主结果板保留比设置面板更强一级的硬阴影；弹层只随现有面板阴影令牌缩减投影，不更改结构。能力值基础标签与紧凑变体均减轻描边，保留虚线和键盘焦点；临时标签仍用完整领域前景色描边。特殊禁用与领域选项填色优先于普通控件表面。伤害条新增独立 CSS 类提供内侧亮边，保持计算及坐标逻辑不变。

Reason:
把样本的视觉意图延伸到实际重复组件，同时尊重现有信息、领域语义与响应式尺寸约束。生产改动继续使用现有组件与共享样式。

Follow-up:
浏览器验证桌面、移动端和按压/焦点状态。

### 5. 统一全产品的边框与模式控件

Type: unresolved-implementation-decision

Context:
用户批准全局统一普通 UI 细边框，并保留焦点、滑块、会心端点和选中指示的粗线。两处模式切换曾各自内联相同的样式，未共享 TrackOption 的调整。

Decision:
扩展现有 shadcn Toggle 的 hud 变体，供招式类别和能力值模式共用。外框使用 hud-frame，候选项保留较淡的 card-border，选中仍可用 ink；共享 chip 阴影改为底边偏移。分组分隔线减为 1px，通过原有颜色和间距维持分组。所有普通 UI 的 border-2 和 1.5px 装饰框均移除，状态指示例外保留。

Reason:
统一厚度但保留边框的角色差别，并消除两处重复样式继续分叉的风险。

Follow-up:
完成源码扫描、桌面/移动端和设置弹层视觉检查；构建及 15 项相关测试通过。
