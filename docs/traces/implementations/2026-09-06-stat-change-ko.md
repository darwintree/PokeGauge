## Entries

### 1. 亲子爱支持边界

Type: tradeoff

Context:
当前 calc 0.11.0 已在亲子爱增强拳追加攻击前增加一级攻击，但不返回一般追加效果的条件分布。其他亲子爱降防或概率加攻需要按首击触发结果重建追加攻击，再保留结束阶级。

Decision:
本轮复用增强拳已有段间伤害，并在命中后向第二次使用传递两级攻击；其他亲子爱能力变化暂缓，在相关招式选择上保留提示。原生多段不增加新的能力变化模型。

Reason:
遵循用户“顺手支持，否则暂缓”的复杂度边界，避免引入段间触发历史或通用状态机。

Follow-up:
None.

### 2. 条件查询与输入兼容

Type: tradeoff

Context:
降防或加攻只影响第二次使用，单段的触发概率与伤害随机数独立；已支持的亲子爱增强拳每次完整命中固定加两级。需求未规定状态表示。

Decision:
保留第一次分布，在第二次查询边界按是否命中、触发概率和树果状态生成至多四种伤害分布并缓存。通过公开 calc 接口重新计算改变阶级后的伤害，限制阶级在 -6～+6。不改变保存输入；有阶级延续的计算身份纳入初始 calc 上下文，避免初次伤害相同、后续行为不同的情景误合并。

Reason:
当前最多两次同招式使用，无需为第一次的每条伤害路径新增阶级字段；条件概率混合足以保留与树果、未命中的关系。

Follow-up:
None.

### 3. 招式与特性边界

Type: interpretation

Context:
当前警告目录列出目标降防、简单自身加攻，以及自身降攻或复合能力变化。用户要求降防和加攻，没有要求扩展所有能力变化与特性支持集合。

Decision:
覆盖目录中的 23 个目标降防招式及 6 个只提高攻击或特攻的招式。自身降攻、全能力提升等保持原警告。强行已受支持，因此抑制这些追加效果；其他尚未支持的特性继续按已有中性占位与提示处理，不在本轮改变特性支持集合。

Reason:
兑现现有输入下明确的效果，避免将本轮扩大成特性、道具和完整战斗模拟补全。

Follow-up:
None.

### 4. 统一段间状态结算

Type: tradeoff

Context:
用户修订范围，要求补齐亲子爱并采用统一框架。第 1、2 条的暂缓和仅跨次混合方案已不足以保留首击伤害与降防事件的关联。

Decision:
将树果消费与本次能力变化次数共同放入 Resolution State。每段由进入时的变化次数选择公开 calc 生成的伤害行，结算独立会心与伤害随机数，再按追加效果概率更新状态；只合并同伤害、同状态的路径。第二次查询复用同一编译／结算流程，缓存不同进入状态。无需枚举完整历史或为亲子爱增加独立概率计算器。calc 已自动处理的增强拳首击加攻在适配层复用，避免重复施加。本条取代第 1、2 条中的暂缓和跨次混合实现选择。

Reason:
当前每个已审核招式只有一种相关阶级变化，变化次数足以还原当前阶级（含 -6～+6 上下限）。亲子爱只是两段的输入，状态与概率规则不需要按招式分叉。

Follow-up:
None.
