# Implementation Trace: Hit Composition

Date: 2026-09-06
Source: [已确认讨论](../discussion/2026-09-06-hit-composition.md)
Language: 中文

## Entries

### 1. calc 与组合执行层的职责

Type: tradeoff

Context:
PR #6 依赖 ADR-0001 的本地单段 kernel，但当前 ADR-0007 已改用 calc。calc 0.11.0 本身生成逐段伤害矩阵，包含递增威力、段间修正及亲子爱第二击。

Decision:
保留 calc 作为伤害来源，适配器读取逐段矩阵。产品执行层负责段数概率、命中控制、逐段独立会心与 roll，以及跨执行树果状态；不再只取矩阵第一行，不额外重复生成 calc 已计算的第二击。组合规则采用受限的顺序段列表与段数概率选择，不开放通用递归控制图。

Reason:
复用公开 calculate 接口可保留引擎取整与段间公式，避免用本地公式或内部 mechanics 导入复制伤害实现。未覆盖的其他状态延续仍按已确认过渡策略披露。

Follow-up:
None.

### 2. 现有输入与旧设定

Type: interpretation

Context:
当前输入格式已用于分享与书签，属于稳定契约；连续攻击威力改为只读，但用户只要求不兼容的旧覆盖值失效。

Decision:
保留分享格式版本，在统一领域校验中拒绝不等于当前固定基础威力的原生多段 Snapshot。未修改过的旧设定继续按当前规则重算，不让所有旧链接失效。内部无外部消费者的计算形状可直接重构。

Reason:
精确实现已确认失效范围，同时保持其他已发布输入语义。

Follow-up:
None.

### 3. 两次执行的概率查询与命中展示

Type: tradeoff

Context:
规格要求树果条件状态，未规定累计概率的数据结构；经典模式还会让不同数值命中获得相同 KO 数学结果，但逐段详情需要实际命中数值。

Decision:
按攻击位置聚合同伤害与状态的路径；第二次执行用按伤害排序的后缀概率查询，避免展开两次完整笛卡尔积。多段展示按每次检查的命中率保留必要分组，但共享相同 KO 计算；经典模式的 90% 逐段命中说明仍为 90%，不因假定命中而改成 100%。

Reason:
状态条件必须保留，完整历史与第二次累积分布没有当前消费者。展示事实与概率模式假设不同，不能从 KO 命中概率反推每次检查的数值。

Follow-up:
None.

### 4. 当前道具与其他状态的边界

Type: scope-boundary

Context:
现有道具目录是已审核的固定集合，尚无机变骰子；亲子爱和连续攻击还可能牵涉其他战斗状态。

Decision:
本轮接入现有支持集合中的连续攻击规则、连续攻击特性与亲子爱，以及现有全部 18 种抗性果消费。不扩充未提供的道具目录；不将其他状态变化伪装成已支持。相关招式与亲子爱位置披露未延续的其他跨次变化。

Reason:
依照用户确认的逐渐补齐策略，兑现当前范围内机制，避免为尚不存在的输入新增接口或中间结果分类。

Follow-up:
机变骰子等新增道具应与目录审核一并实现。

### 5. 亲子爱的引擎消费边界

Type: discovered-constraint

Context:
交叉测试发现 calc 0.11.0 的亲子爱递归计算保留原抗性果，追加攻击错误地再次减伤；原生连续攻击按 hitCount 正确只减首段。

Decision:
适配器在确认亲子爱首击消费抗性果后，保留首击，采用移除抗性果后由同一公开 calculate 接口产生的追加攻击结果。不手动把已取整伤害乘二。

Reason:
必须兑现本轮明确要求的消费行为，同时保留 calc 的追加攻击取整和段间能力变化。独立测试覆盖普通及会心追加攻击与无果情景一致。

Follow-up:
升级 calc 时复核此适配；若上游已修复可简化。
