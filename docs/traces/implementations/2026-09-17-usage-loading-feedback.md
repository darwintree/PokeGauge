# Implementation Trace: 使用率明细加载反馈

Date: 2026-09-17
Source: 用户要求检查编译覆盖、补充宝可梦使用率加载提示并检查关联交互
Language: zh-hans

## Entries

### 1. 等待实际请求完成并提供非阻塞反馈

Type: unresolved-implementation-decision

Context:
默认推荐在 5 秒后放弃，但底层静态资源和在线请求分别有 10 秒与 15 秒超时；用户未指定等待、失败恢复方式。

Decision:
删除推荐层的重复超时，沿用传输层超时。工作区显示当前对阵的使用率加载状态，加载期间仍可手动编辑，失败可重试。重试只重建推荐目录，已有手动选择沿用 selection 的保护规则。

Reason:
避免尚未结束的请求被误判失败；不延长魔法数字，也不另建请求状态仓库。沿用稳定的用户选择、分享和存档语义，内部加载实现直接修正，不保留兼容分支。

Follow-up: None

### 2. 明细状态不以排行变化或请求成功代替

Type: unresolved-implementation-decision

Context:
用户未指定失败粒度；既有特性与性格读取将失败折叠为成功，道具需双方都失败才报错。刷新只有排行指纹变化时才重建推荐，Smogon 又把请求错误折叠为空数据。

Decision:
保留各分类的失败状态，任一侧道具或特性失败即显示部分失败；手动刷新成功后，即使排行相同也重新读取推荐。Smogon 共用按 URL 缓存的统计请求，失败清理缓存并向上传播。顶部提示服务当前对阵，加载期间可手动选择；无推荐招式时提示添加或切换分类。

Reason:
沿用现有目录和 selection 状态即可区分加载、失败、无推荐，不引入第二套宝可梦请求状态。手动编辑与已恢复配置的保护仍由 selection 统一处理。

Follow-up:
来源／规则目录的切换仍缺少独立的加载失败反馈；本次未扩展设置交互。
