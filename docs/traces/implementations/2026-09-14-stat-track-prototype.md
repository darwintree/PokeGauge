# Implementation Trace: Stat Track 交互原型

Date: 2026-09-14
Source: 用户请求通过 prototype 探索默认选项、独立模式按钮、弹出编辑
Language: 简体中文

## Entries

### 1. 对比编辑容器

Type: unresolved-implementation-decision

Context: 用户未确定对话框或其他弹出形式。
Decision: 在现有页面使用 ?prototype=stat-track&variant=A|B|C，比较居中对话框、锚定浮层、侧边面板。默认 A。沿用浅色 HUD 与 shadcn，变化/动效/密度为 3/2/8。
Reason: 放在真实侧栏密度下评估新增与区间调整。仅开发模式可用；运行 pnpm prototype:stat-track。
Follow-up: 用户选择方案后再正式实现并将原型归档至 throwaway 分支。尚无已验证的产品决策。

### 2. 临时状态范围

Type: tradeoff

Context: 本次验证操作方式，不改动已有领域模型、结果信息层级或持久化。
Decision: 原型读取真实预设及能力边界，用独立内存状态演示选择、新增、取消、区间编辑。选项转区间取包络；返回选项暂时保留原选择，不演示正式端点转换。刷新或更换宝可梦/招式类别重置状态。原型操作不联动伤害结果，底栏明确提示。
Reason: 避免试验交互污染正式场景。完整转换仍以 ADR 0003 为正式实现依据。
Follow-up: 选定 UI 后将交互接入正式单一集合模型，不能将此演示状态逻辑直接用于产品。

### 3. 就地浮窗与移动端结果预览

Type: unresolved-implementation-decision

Context: 用户选定就地浮窗，要求保留旧调节视觉，并在移动端通过“同时预览伤害”将调整区放到结果顶部；尚未明确预览时的草稿、返回和保存行为。
Decision: 保留 StatRangeInput、StatPresetChoices 和 StatValueChip，直接复用档位色、吸附刻度、选中点标记、黄色草稿点、32px 手柄命中范围、±1 微调与能力分配角标。浮窗和结果顶部使用同一组状态；点击预览切换现有移动端结果页，顶部放非固定调整面板，“返回浮窗”带回草稿。使用现有 lg（1024px）参数/结果分栏断点，桌面不显示预览按钮；变为桌面宽度时编辑区回到浮窗。
Reason: 变更编辑位置，不重做经过调整的领域可视化。复用现有草稿伤害管线，预览结果与调整值保持一致。区间沿用旧编辑器实时更新、完成即关闭的行为；新增草稿可取消。
Follow-up: 本轮仍为开发原型。正式入口保持不变；正式迁移时移除原型开关并完成发布文案。

### 4. 真实预览的内存隔离

Type: tradeoff

Context: 上一轮独立演示状态无法驱动真实伤害结果；直接接入状态钩子会自动保存场景与用户选项。
Decision: 原型接入现有单一选中集合与伤害管线，useScenarioState 增加默认开启的持久化开关。原型关闭自动快照和预设写入，新增/删除预设进入按宝可梦区分的内存池。正式调用维持默认保存行为。原型恢复对阵时以选项模式开始。此条取代第 2 条的独立转换演示。
Reason: 可以实测新增、区间和模式切换对伤害的影响，同时不污染本地预设与场景快照。
Follow-up: 已用状态钩子测试验证新增与预览不写存储；手机 390px 下验证浮窗、结果顶部、返回草稿及新增选项。正式迁移时评估删除仅用于原型的内存开关。

### 5. 空 Stat Track

Type: interpretation

Context: 用户要求新逻辑允许不选择 Track，并让结果区没有结果；未指定区间模式下的空状态入口及模式切换行为。
Decision: 原型允许取消最后一个选项，区间模式提供“清空”。使用 stat-clear 选择命令清除选中集合和临时端点，保留选项池。空状态切换模式后仍为空，只有重新选值或调整区间才产生选择。任一侧的计算用选中集合为空时输出零结果，复用现有结果空态；新增草稿仍可按既有草稿管线预览，取消草稿回到空态。
Reason: 空选中是用户明确选择，不应在切模式或异步默认加载时被默认值覆盖。入口仅接入当前开发原型。
Follow-up: 状态测试覆盖攻防清空及默认刷新；浏览器验证取消最后一项后显示 0 条结果，空状态切模式保持“未选择”，重新选择恢复结果。

### 6. 常驻三角微调

Type: unresolved-implementation-decision

Context: 用户要求将点击后展开的 +/- 改为数轴两侧常驻的左右三角图标；区间含两个端点，未指定微调目标。
Decision: 左三角减 1、右三角加 1，默认调整下限；点击、聚焦或拖动端点后改为调整该端点，并用圆环显示目标。端点交叉后目标随拖动角色交换。区间收敛为一个点时，两侧按钮整体平移该点；新增草稿始终调整草稿值。达到边界禁用对应按钮，保留原 32px 手柄命中区，三角按钮为 24px 触控目标。
Reason: 常驻控件不再引起垂直布局变化；一个明确的微调目标避免增减哪一端的歧义。使用现有 lucide 三角图标及 shadcn Button。
Follow-up: 浏览器已验证 182 → 183 → 182，组件测试覆盖下限、切换上限和新增草稿微调。

### 7. 正式版恢复语义

Type: interpretation

Context:
原型为方便比较而将恢复的模式强制切为选项，并禁用保存；用户确认原型后要求正式实现，未另行指定既有保存数据的迁移方式。

Decision:
正式版使用既有保存通路，按保存的模式恢复，新对阵仍默认选项模式。空集合可本地保存和恢复，切换模式保持为空；首次调整区间会建立端点选择。书签及分享继续沿用完整 Scenario Setup 的校验规则。

Reason:
保留用户已保存的有效设定，同时让空选择成为统一状态语义，而不是 UI 的特殊清空分支。

Follow-up:
None.
