# Implementation Trace: Expanded Stat Track mode panes

Date: 2026-08-20
Source: 用户选定原型 E，并要求点 `+` 后布局不抖动
Language: zh-Hans

## Entries

### 1. 草稿轴留在区间栏原地切换

Type: tradeoff

Context:
原型 E 把草稿轴插进选项栏，跟 `+` 同一栏，但点 `+` 会突然多出一条（防守则两条）轴和「在轴上落点」文案，布局被顶抖。E 的核心是分区点选切模式，不是轴必须搬家。

Decision:
区间栏始终渲染同一条轴。点 `+` 只把这条轴就地切成草稿点；确认/取消占区间栏标题行里已预留的 `h-7` 槽，和「当前」徽章互换。加点过程中区间栏不降透明度，避免草稿轴落在被禁用的一栏里。

Reason:
轴高度本来就在，确认行也不新增垂直空间，点 `+` 不再插入 DOM 块。分区激活（点栏切区间/选项）仍在。

Follow-up:
None.

### 2. 未选中栏 hover，草稿期把工作面拉回轴上

Type: decision

Context:
未选中 ModePane 没有 hover，点起来像死面。点 `+` 后 mode 仍是选项，「当前」徽章留在下方，草稿轴在上方未高亮栏里，看不出要去上面拖。

Decision:
未选中栏用 `hover:bg-token-bg/70` + 标题变 ink，按下预览选中底。加点时区间栏改亮、标题换成「在轴上拖动」（静态文案，点它不会取消草稿）、确认行仍占原槽；草稿点改黄钮，整条轴可点可拖，点空白处直接落到该处。选项栏此时不加「当前」。

Reason:
hover 跟折叠浅井同一套可点预览。加点时把选中面和文案都送到轴所在栏，不必再插一行提示（会抖）。整轴可点是因为 14px 圆点不够当唯一落点入口。

Follow-up:
None.
