# Implementation Trace: Choice Pool 视觉调整

Date: 2026-09-05
Source: 用户要求按自主审美改进当前分支的前端，并兼顾四种语言及移动端；docs/traces/discussion/2026-08-31-choice-pool-external-selection.md；design.md
Language: 简体中文

## Entries

### 1. 选项常驻后的视觉容器与空间分配

Type: unresolved-implementation-decision

Context:
讨论确定了选项池常驻与双行结构，但没有定义常驻后密集 Track 的容器层级。当前 300px 侧栏内，每个半宽 Track 都有粗框和阴影，英文名称与图标频繁换行。

Decision:
把 Track 收入一个共享白色 HUD 外框，内部使用细分隔线；攻防继续成对排列且保持原顺序。天气占用末行全宽。桌面侧栏在 1024px 起使用 336px、1280px 起使用 360px。沿用现有字体、语义色与选中样式，增大常驻选项的字号和间距，触控设备采用更大的点击区域。

Reason:
符合 design.md 的外框承重、内部平整原则，并为英文和日文提供实际排版空间；无需改变选择状态、计算逻辑或结果信息结构。

Follow-up:
检查四种语言和手机、平板、桌面视口，并根据实际截图修正。

### 2. 长名称环境选项的排布

Type: tradeoff

Context:
四种语言、五档宽度的首轮截图没有溢出，但 360px 手机上的英文和日文场地选项几乎逐项换行，与右侧仅两项的墙产生大面积空白。

Decision:
场地、墙、天气按原有顺序各占整行；攻防配对的能力值、阶级、特性和道具仍用两列。允许选项文字自然换行；触控设备的常驻 chip 至少 44px 高。

Reason:
环境选项不具有攻防配对关系，全宽布局更适合不同语言的名称长度，同时保留全部选项可见和标题、选项分行的契约。

Follow-up:
None.


### 3. 分区后的窄栏编辑与属性素材

Type: unresolved-implementation-decision

Context:
用户通过截图指定攻击方、防御方和公共场地的独立分区，并要求墙归防御方、场地天气使用 PokéSprite 属性图标。分区在窄栏中如何展开能力值编辑器、使用哪套属性素材及加载方式未指定。

Decision:
招式保留独立横栏。攻防分区默认两列、独立高度；容器不超过 560px 且任一能力值编辑器展开时，两分区改为单列以保留完整编辑宽度。公共场地内部的场地、天气各占一行，五个图标在 360px 手机中仍能同排。
使用 PokéSprite 的 `misc/types/gen8` 圆形无文字图标，固定源提交 `c5aaa610ff2acdf7fd8e2dccd181bca8be9fcb3e`，仅将所需八张原图加入本地资源并保留来源和版权声明。场地对应电、草、超能力、妖精；天气对应火、水、岩石、冰；无条件复用 CircleSlash。按钮保留本地化无障碍名称及完整名称、说明提示，青草场地保留警告标记。

Reason:
双列保留用户标注的左右关系，展开后给复杂编辑器足够空间。小型固定素材集本地打包可避免增加外链加载依赖；通用属性符号不随语言改变宽度。

Follow-up:
None.


### 4. 移动端选项密度

Type: interpretation

Context:
用户反馈移动端 Choice 选项过高，希望缩小；具体尺寸未指定。

Decision:
移动端及粗指针设备的常驻选项最小高度从 44px 改为 36px，图标和添加按钮统一 36px，文字垂直内边距缩至 4px，选项间隔从 8px 改为 6px。长名称继续自然换行。

Reason:
让多组常驻选项的纵向占用明显减少，维持可辨认的图标和分离的点击区域。

Follow-up:
None.


### 5. 桌面侧栏的紧凑密度

Type: interpretation

Context:
用户认可移动端尺寸，但反馈桌面参数区图标偏大、换行多，具体紧凑尺寸未指定。

Decision:
1024px 及以上、非粗指针设备使用紧凑规则：文字选项最小高 28px、字号 11px，图标按钮 30px、素材 24px，选项间距 4px，Track 标题高 32px，左右及底部留白 8px。分区间距缩到 8px，纵向块间距 12px。移动端和触控设备继续使用已确认的 36px。

Reason:
优先减少半栏的控件与间距占用，让多个道具和阶级能同排；不挤占伤害结果宽度，不截断长名称。规则同时覆盖无指针的键盘设备；粗指针继续保持触控尺寸。

Follow-up:
None.

### 6. 桌面侧栏滚动边界

Type: unresolved-implementation-decision

Context:
用户截图指出横向滚动不合理、纵向原生滚动条笨重。开启原生滚动条并选择防御方烈咬陆鲨后复现：侧栏 clientWidth 345px、scrollWidth 349px。形态按钮定位为 right:-8px，超过滚动区右边界。

Decision:
桌面设定区内的形态按钮定位改为 top:4px、right:4px，保持其完整点击区域位于卡片内；不隐藏横向溢出来掩盖源头。侧栏保留原生纵向滚动和稳定 gutter，使用 thin、透明轨道、语义色滚动滑块，hover/focus 时提高可见度。提供 WebKit 滚动条样式作为兼容回退。

Reason:
修正实际越界控件可同时消除多余横向滚动与顶部裁切；原生细滚动条保留鼠标拖动和键盘滚动，无需引入新的滚动组件。

Follow-up:
后续视口回归包含防御方多形态与可见原生滚动条。

复查补充：移动端同一个按钮也超出设定区 4px，虽因外层留白没有出现页面横向滚动，仍将设定区内的边界修正统一应用于各尺寸。36px Choice 尺寸保持不变。


### 7. 场地波纹底座

Type: unresolved-implementation-decision

Context:
用户指定参考图方案四作为场地底座，再叠加属性图标；具体变体和小尺寸绘制方式未指定。

Decision:
采用方案四第一种简洁断续椭圆的思路，以两层错位开口的 CSS 椭圆组成静态底座，上方保留 PokéSprite 属性图标。桌面整体 24px、移动端 28px，属性符号占整体的 66%。无场地继续使用原有禁用符号。

Reason:
两层轮廓在紧凑按钮中保持清楚的地面透视，避免细碎粒子缩小时产生噪点；复用现有属性资源和按钮尺寸，无需新图片依赖。

Follow-up:
None.


### 8. C 方案的小尺寸矢量定稿

Type: unresolved-implementation-decision

Context:
用户确认整体重绘的 C 扩散能量场概念稿。概念稿含渐变，未规定正式素材格式、曲线尺寸及选中背景适配。

Decision:
用四张本地 SVG 替换场地 PNG 和旧 CSS 底座，统一倾斜椭圆、两段 150 度扩散弧、圆头描边和白色属性符号。使用平涂属性色，电属性略偏深金黄以改善黄色选中背景上的辨识；复用现有 24px/28px 图标尺寸。天气素材不变。

Reason:
矢量轮廓在小尺寸下稳定，去除分离底座和渐变后视觉语言统一；尺寸和提示继续由现有按钮承担。

Follow-up:
None.


### 9. 天气 B 方案与不可选天气

Type: unresolved-implementation-decision

Context:
用户确认天气 B 色块徽记方案，要求七种天气进入前端，后三种不可选。未规定展示项如何与计算目录分离及窄屏排列。

Decision:
七张本地 SVG 统一色块和白色符号。大日照、大雨、乱流作为天气 Track 内的展示列表，用已有 disabled 选项和本地化不可选提示呈现，不扩展计算 Weather 联合类型。三项作为一个不拆行的组，窄屏一起换到下一行。

Reason:
展示完整图标家族而不让尚不可选的天气进入状态、分享或计算；成组换行避免仅一个禁用项落到第二行。

Follow-up:
None.


### 10. 按 B 概念稿恢复天气细节

Type: tradeoff

Context:
用户指出 SVG 与确认的 B 图在细节上有差异，要求比较重绘。初版以等宽线段替代沙暴与乱流的宽窄变化，雨滴简化成直线，导致视觉偏差。

Decision:
重绘七种天气的轮廓与比例；沙暴和乱流恢复曲面色块、卷曲端部与宽窄变化，大雨恢复渐尖雨滴。保留矢量平涂形式与 24px/28px 尺寸，调整边缘留白以防白色符号切穿外轮廓。

Reason:
恢复已确认稿的关键造型，同时保留小尺寸可辨识的间隔；不将概念稿中的渐变或细微光泽带入小图标。

Follow-up:
None.


### 11. 场地与天气选项池

Type: interpretation

Context:
用户要求场地和天气采用能力阶级模式，并取消各自独占一行；未规定不可选天气的位置及已有记录处理。

Decision:
公共场地内两列并排；初始池为 none，添加弹窗列出池外选项并展示名称与说明，添加即选中，取消选择保留池条目。后三种不可选天气放入天气添加弹窗，复用特性禁用样式。天气即使支持项全部入池仍保留添加入口，供查看不可选天气。
本地 TrackState 增加 weatherPool/terrainPool；旧本地记录从 none 与已有选择补齐，分享恢复同样重建池而不改变分享格式。特性投影同步入池，类别切换保留池，身份切换沿用现有场地/天气重置规则。

Reason:
与能力阶级的池/选择分离保持一致；小目录弹窗显示完整说明，兼顾触控与长语言。共享字段保持现有消费者兼容，尚在工作区迭代的常驻目录直接替换。

Follow-up:
None.

### 12. 顶部身份卡片交互与原型归档

Type: interpretation

Context: 用户确认 A 铭牌方案，要求补齐 hover；具体交互幅度未规定。

Decision: 沿用共享外框、64px 精灵图与 ATK/DEF 标记；悬停显示浅色背景并将精灵上移 2px，按压回落，键盘焦点使用内描边。减少动态效果时关闭位移。通过现有选择器的 compactSide 参数启用布局，保留 landing rail 行为。

Reason: 在紧凑共享边框中提供明确反馈，避免整个卡片上浮产生边界错位。
