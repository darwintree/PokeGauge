# 实数值模版 讨论记录

对应 issue: [[20260628_open_define-default-names-for-stat-value-templates|Define default names for stat-value templates]]（§12 默认命名）

UI 定稿：§7–§11（原 Wrap grid 原型已清除，以本 trace 为实现依据）

## 1. 领域实体 — 实数值模版

问题：攻击方/防守方「预设」应抽象成什么；与现有性格+努力 preset 的关系。

决定：正式术语 **实数值模版**（Stat value template）。存 **最终实数值**（进攻单 stat；防守 `{HP, 防}`），**不含性格**。系统模版与用户模版同构；若现有 preset 模型不一致，实现层 **泛化** 为实数值 first-class，spread 配方仅用于 seed 系统默认档。

## 2. 作用域与生命周期 — 用户模版

问题：用户模版存哪、能否删除、能否跨宝可梦复用。

决定：**按宝可梦** 保存；用户创建的模版 **可删除**；系统模版 **不可删**；v1 **仅 `localStorage`** 分桶，**不做** import/export 与跨设备同步。

## 3. 预设区 ↔ 数轴选段

问题：两种模式是否共存；切换时状态如何对齐。

决定：**XOR**。预设区 = 多选具名点（row product = 选中数）；数轴选段 = 合法区间内一段（row product = 1）。**Preset → Range**（range 未手动拖过）：选中模版实数值 → 各轴外包围。**Range → Preset**（对称回写）：对每个轴端点（单点 1 个，band 最多 min/max 2 个），精确匹配已有模版则选中，否则新建 **临时模版** 并选中；防守 HP / 防 **分轴** 同一规则。

## 4. 临时实数值模版

问题：何时产生、如何持久化、何时丢弃、如何与用户模版区分。

决定：数轴 → 预设且端点无法匹配已有模版时产生（最多 2 个/轴 band）；**未持久化** 的在 **离开 matchup 或刷新** 时丢弃；持久化 **可不命名**（默认名规则见 [[20260628_open_define-default-names-for-stat-value-templates]]）；**系统 / 用户 / 临时** 三者需 **视觉区分**（临时：虚线等；用户：中性 chip、不上 tier 色；系统：tier 色）。

## 5. 添加模版 vs 临时模版

问题：用户主动「添加模版」与对称回写产生的临时模版路径是否相同。

决定：**不同**。「添加模版」→ 单点数轴（prod 吸附逻辑；防守双轴）→ **确认即持久化** 并自动选中。数轴 → 预设回写 → **临时** → 可选持久化。

## 6. 系统默认档与 Default view 选中集

问题：系统模版有哪些；首次进入默认选中哪些。

决定：**进攻** 系统三档 **0 / 32 / ex**（能力点数语义；**不用 `max` 标签**）；**防守** 三档 **0 / 32HP / ex**。Default view：**进攻** 默认选 **32 + ex**；**防守** 默认选 **32HP**；该宝可梦下 **全部已持久化用户模版** 一并默认选中；系统 **0** 档与 **临时模版** 不参与默认选中。

## 7. 能力点数 · 标签引擎 · 卡片展示

问题：卡片主标签与实数值 / spread 的关系；实数值如何映射为标签；努力分配 detail 是否上屏。

决定：

- 正式术语 **能力点数**（Ability points）：Champions 点数 `(EV+4)/8`，受修正 stat 可选 `+/-` 后缀（HP **无**后缀）。**不是**模版实体字段；性格不写入模版，仅体现在能力点数标签上。
- 卡片 **主标签** 用能力点数及 shorthand（`0`、`0+`、`17`、`32`、`32HP`、`ex` 等），**不**默认展示实数值，**不**展示努力分配 detail（如「252 物攻 / 0 其余」）。
- 实现 **标签引擎**（实数值 + 物种 + stat 轴 + 当前 spread → 标签）：
  1. 若当前 spread 的能力点数模式 **等价 ex** → 仅展示 **`ex`**（进攻：`32` 点 + **+修正**，即 `32+` 的 shorthand；防守：`32HP` + `32` 防 + **防 +修正**，即 `32HP32Def+` 的 shorthand）。
  2. 否则 → 展示 **无修正** spread 的能力点数（如 `0`、`17`、`32`）；防守 HP-only 中间档 → shorthand **`32HP`**（`32` HP 点、防 `0` 点、无修正）。
- `ex` 与默认无修正 **不冲突**：ex 档实数值自然落在 +修正模式，由规则 1 输出 `ex`。

## 8. 可选「显示实数值」

问题：用户如何查看实数值而不污染默认紧凑布局。

决定：每个 track 预设区提供 **「显示实数值」switch**；**关闭** 时不出现实数值；**开启** 后在 **卡片外部下方** 展示对应实数值（如 `157`、`168 / 92`），不进卡片内部。

## 9. 分配切换 — 语义 · 位置 · 样式

问题：⟳ 分配切换的行为语义；控件放在哪、长什么样。

决定：

**语义**

- **纯展示**：实数值模版与 pipeline **只读实数值**；切换 spread 仅改能力点数标签，不影响 row product、匹配键或持久化内容。
- **全枚举**：该物种所有合法 spread 中算出该实数值（防守为 `{HP, 防}` 对）的全体；能力点数标签相同（含 `+/-` 档）→ 合并为一项。例：`0+` 切到下一项可为 `17` 等（随种族值变化）。
- **性格展示**：不按 nature 名；受修正 stat 仅 **无修正 / +修正 / −修正**（后缀 `∅` / `+` / `-`）。
- **粒度**：进攻单 stat 一个 ⟳；防守 `{HP, 防}` **整组 joint** 一个 ⟳。
- **默认**：全部模版统一，由标签引擎 §7 输出（非 seed pinned）；多分配时默认 **无修正** spread。
- **不持久化** `activeAllocation`；刷新后重新由引擎决定。

**位置与样式**

- 放在 **卡片外部右侧**（与卡片顶对齐）；控件含 **⟳ icon + `1/2` 计数**；仅 `allocations.length > 1` 时显示。

## 10. 预设区布局 — Wrap grid

问题：多选选项的整体排布与信息/空间权衡；是否拆分系统/用户 lane、是否用 type icon。

决定：采用 **Wrap grid**（flex-wrap，项宽随标签内容）。**统一列表**（系统→用户→临时排序），**不按 lane 拆分**；**不用** type icon（Bookmark/User 等）；类型仅靠 **边框/底色/tier 色** 区分；标签 **完整展示**，禁止 truncate / line-clamp；容器宽度对齐 sidebar（**`w-72` / 18rem**）。

## 11. 添加模版数轴交互

问题：添加模版时数轴拖动约束是否与生产一致。

决定：复用 prod **`StatRangeAxis`**（进攻 collapse 单点；防守 HP + 防各单点），吸附与拖动逻辑与生产 **一致**。

## 12. 默认命名

问题：持久化时默认名称如何生成。

决定：**本讨论不定稿**；由独立 issue [[20260628_open_define-default-names-for-stat-value-templates]] 收敛。
