# 携带道具伤害与能力值修正编译讨论记录

对应 spec change: None.

## 1. 伤害公式 Module 的 Interface

问题：新增携带道具效果是否需要改变伤害 kernel 的 Interface，或让 kernel 识别具体道具。

决定：保留现有 `calculateDamageRolls(CompiledDamageInput)` Interface；kernel 不识别携带道具，compiler 负责将道具效果归入现有公式阶段。

## 2. 修正值、阶段与舍入

问题：道具修正应采用简化倍率还是研究确认的 Gen 9 整数算法。

决定：采用研究确认的 4096 整数修正值、阶段、顺序、舍入与叠加算法；compiler 向 kernel 提供各阶段最终修正标量。

## 3. 道具效果采用的输入

问题：道具效果应基于上游模版原值，还是当前 Scenario 中用户已编辑的输入。

决定：基于当前 Scenario。Base Power 道具作用于 Move snapshot 当前威力；攻防道具作用于当前 build、范围端点及能力阶级所形成的公式输入；不回看上游模版原值。

## 4. 未满足激活条件时的状态

问题：白名单道具的属性、类别、克制或身份条件未满足时，应采用何种来源状态。

决定：条件未满足时以中性倍率编译并记为 `inactive`；`neutral` 仅用于 `none`、Unknown Mega Stone 等明确中性身份；部分支持警告不改变来源状态；白名单核心效果不使用 `unsupported`。

## 5. 缺少战斗历史输入时的处理

问题：抗性树果是否需要替身、可食用状态、既往消耗等额外战斗状态才能参与编译。

决定：只使用当前模型已有输入。抗性树果按来袭属性与克制条件激活，Chilan Berry 只要求普通属性；不判断替身、`eatItem()` 或既往消耗，默认当前仍持有且可以生效；N-hit 继续复用静态树果效果，不新增 Track、开关或 `unsupported` 分支。

## 6. 万能伞的支持边界

问题：万能伞的哪些持有方和天气效果进入本轮伤害编译。

决定：只实现防守方持有万能伞时对普通晴雨火／水伤害修正的抑制；攻击方及特定招式、命中率天气交互不进入本 ticket 的伤害编译。

## 7. 与其他决策 ticket 的边界

问题：身份／形态门控和命中率／要害道具是否在本 ticket 内一并决定。

决定：身份与形态的精确门控留给对应 identity ticket；命中率与要害道具留给 probability ticket。本 ticket 只固定伤害与攻防能力值效果的编译契约。
