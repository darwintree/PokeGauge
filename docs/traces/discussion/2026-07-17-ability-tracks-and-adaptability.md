# Ability Track 与适应力契约讨论记录

对应 spec change: None.

## 1. Track 形态与选择下限

问题：双方特性如何作为 Scenario 配置，以及是否允许空选择。

决定：攻击方与防御方各有一个 Ability Track；均为 multi-select track，选中特性即视为启用，不设额外开关，且始终至少选择一项，最后一项不能取消。

## 2. 合法候选来源

问题：Ability Track 应从哪个身份和数据集合取得候选。

决定：候选按当前 Battle Pokémon identity 读取 PokeAPI 当前特性，以 ability numeric id 标识，包含隐藏特性、排除历史特性；隐藏特性不额外标注。

## 3. 默认选择与重置

问题：初始与重置时应选中哪些合法特性。

决定：按当前 Champions 双打赛季的特性使用率顺序，默认只选首个仍合法的特性；该语义是“最常用”而非“官方推荐”，界面无需额外标注。无匹配、无数据或数据失效时全选全部合法特性；重置遵循同一规则。

## 4. 宝可梦变更生命周期

问题：matchup 或其他 Track 变化时，Ability Track 如何保留或重建。

决定：更换攻击方或防御方时，只按默认规则重建被更换一方的 Ability Track；另一方保留。Move side、Move snapshot 及其他 Track 变化不重置双方特性选择。

## 5. 本轮支持边界

问题：哪些特性产生计算效果，以及未支持特性如何参与 Scenario。

决定：本轮只有适应力产生特性计算效果。其他真实特性仍可选择，以中性修正参与计算与效果等价合并，并标记“效果暂未支持”；不得把未支持表述为已判断未生效。

## 6. 适应力语义

问题：当前 ruleset 和产品范围内，适应力何时改变伤害。

决定：攻击方持有适应力且招式属性属于攻击方原始属性时，将 STAB 从 `1.5×` 改为 `2×`。攻击方使用非本系招式或防御方持有适应力时均不改变本次伤害，归入“未生效”；界面不额外显示“已支持”。太晶化不在本轮范围。

## 7. 结果标注

问题：生效、未生效与未支持的特性来源如何展示。

决定：生效的攻击方适应力在结果行内显示为“适应力”；已判断未生效的适应力默认折叠为“未生效”；其他特性在 Track 选项和默认折叠的结果来源中标记“效果暂未支持”。

## 8. 效果等价与来源保留

问题：不同特性选择何时合并，以及合并后如何保留双方来源。

决定：等价键只包含实际生效的特性计算输入；未生效的适应力、未支持特性与其他中性选择可以合并，生效的适应力以 `2× STAB` 形成不同结果。合并来源按攻击方／防御方分别保留，同名特性也不跨双方合并身份，并分别保留“未生效”与“效果暂未支持”状态。

## 9. 排序边界

问题：Ability Track 的完整候选排序是否需要在本轮固定。

决定：默认选项只受 Champions 最常用合法特性规则约束；其余候选排序不在本轮固定，实现时保留可调整逻辑。
