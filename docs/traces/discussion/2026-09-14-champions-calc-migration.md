# Champions calc 迁移讨论记录

对应 spec change: None.

## 1. 核心意图 / Core Intent (Design Tree Root)

> Brief: 采用新版 calc，提供第九世代与 Champions 规则切换，补齐当前因旧版缺少 Champions 支持而不可用的内容。

### 1.1 迁移到哪里？

问题：采用新版 `@smogon/calc` 的 Champions 引擎，还是直接接入 Pokémon Showdown 完整对战模拟器？

决定：采用新版 `@smogon/calc`，在设置中提供第九世代与 Champions 规则切换；Showdown 用作独立对照。

### 1.2 这次做到什么程度才算完成？

问题：让现有功能按照 Champions 规则正确计算并补齐新版引擎已支持的特性，还是同时扩展目前不支持的战斗机制？

决定：不按严格的功能分类划定范围；核心是把当前因旧版缺少 Champions 支持而未支持的内容迁移到已支持状态，例如龙之皮肤。

## 2. 书签与结果

> Brief: 书签只记录配置，不承诺历史计算结果。

### 2.1 旧情景重新计算后，允许结果变化吗？

问题：用户打开旧书签，选择相同，但因 Champions 规则或上游修复，伤害与 KO 概率发生变化，如何处理？

决定：按新规则重新计算，不因结果变化提示用户；书签只记录配置，不承诺结果。

## 3. 上游版本与交付

> Brief: 使用固定上游提交构建接入，后续更新经过验证再更换。

### 3.1 如何跟进尚未发布到 npm 的引擎？

问题：固定一个上游提交、构建后接入并按需验证升级，还是等待正式 npm 发布再迁移？

决定：固定上游提交并构建接入，记录来源，使构建可复现；后续更新经过验证再更换，不自动追随 `master`。正式 npm 包覆盖这些改动后再切回。

## 4. 计算规则设置

> Brief: 两套规则来自同一个新版 calc；支持标记随当前规则变化，书签和分享链接不携带规则选择。

### 4.1 切换的是哪两套引擎？

问题：同一个新版 calc 提供的第九世代 / Champions，还是保留旧版 `0.11.0` 与新版 Champions 切换？

决定：使用同一个新版 calc 的第九世代 / Champions。设置中称为“计算规则”，选项显示游戏规则名称；特性、道具等的支持标记随当前规则变化。

### 4.2 这个选择是否跟随书签和分享链接？

问题：使用 Champions 保存的配置，被当前选择第九世代的用户打开时，沿用当前规则还是切换为 Champions？

决定：使用当前规则。计算规则作为记住用户选择的全局设置，不写入书签和分享链接；打开配置时按当前规则重新计算支持标记与结果。

### 4.3 未设置过的用户默认使用哪套规则？

问题：没有保存计算规则偏好的用户默认使用第九世代还是 Champions？

决定：默认使用 Champions。

### 4.4 切换规则后，已选但不支持的特性、道具如何处理？

问题：例如已选讲究眼镜，从第九世代切换到 Champions 后，不再受支持的已有选择如何处理？

决定：保留选择，标为不支持，按无该特性／道具效果计算；切回支持的规则后恢复生效，不自动删除或替换选择。若不支持的是招式本身，则保留配置并标为不可计算。

## 5. 目录外机制支持

> Brief: 是否支持以实际机制为准，不仅以 Champions 目录资格为准。

### 5.1 Champions 目录外、但机制仍有实现的内容，是否开放支持？

问题：例如 Air Lock 不在 Champions 目录内，但引擎仍有天气压制逻辑，是否允许支持？

决定：支持经过验证、能在当前场景中正确计算的目录外内容；缺失或仅部分实现的效果明确标记。候选目录保持可见，不把未进入 Champions 目录直接等同于未实现。
