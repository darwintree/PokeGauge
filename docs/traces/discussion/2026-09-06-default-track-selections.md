# 默认 Track 选择逻辑讨论记录

对应 spec change: None.

## 1. 精简目标与范围

问题：本轮精简 Setup 展示还是默认结果区行数，哪些 Track 保持现状？

决定：精简默认选择带来的结果区行数。Setup 样式不变；招式、进攻能力值、防守能力值保持当前逻辑；墙保持当前默认逻辑。继续允许多选。

## 2. 道具默认选择

问题：道具如何从使用率推荐中选择默认值？

决定：按原始使用率排名第一项决定，默认仅选一项。当前侧可计算的普通道具直接选中；无计算效果或无法映射时选择中性项，不跳过第一名改选低使用率的增伤道具。其他推荐道具留在 Choice Pool。形态触发道具仅留在池中，不自动切换宝可梦身份；已锁定形态的必需道具继续固定选中。缺少使用率数据时沿用中性回退。

## 3. 天气与场地

问题：特性推荐的天气、场地是否自动选中，冲突和中性项如何处理？

决定：默认选中特性推荐值；多个推荐值冲突时全部选中。有推荐时不同时选中中性项，无推荐时才默认选中性项；中性项始终留在 Choice Pool。

## 4. 特性组合与能力阶级

问题：威吓、不服输等特性如何共同决定默认能力阶级？

决定：威吓默认选中 -1，替换默认 0。不服输单独默认选中 0，+1 与 +2 仅加入 Choice Pool；与威吓联动时默认只选中 +1。如果不服输侧还选有其他特性，则取不同特性组合对应阶级的并集。使用泛化的组合求值与并集编码方式。好胜采用第 8 项规则。

## 5. 特性使用率缺失时的回退

问题：加载初期或缺少使用率数据时是否仍选中全部可选特性？

决定：有数据时继续选择最高使用率特性；无数据时只选身份列表中第一个可选特性，其他特性保留可选；没有可选特性时使用中性项。

## 6. 默认推荐与用户手动选择

问题：特性推荐是否可以覆盖用户已经编辑的天气、场地或能力阶级？

决定：只在新建、相关重置或尚未手动编辑该 Track 时应用默认选择；手动编辑后，特性联动只补充 Choice Pool。

## 7. 已有 Setup 的恢复

问题：分享、书签和恢复的已有 Setup 是否应用新的默认单选规则？

决定：保留已有 Setup 的原有选择，包括多选，不应用新默认压缩它们。

## 8. 好胜的默认阶级

问题：好胜是否采用与不服输相同的潜在增益与明确联动区分？

决定：单独选择好胜时默认选中 0，+2 仅加入 Choice Pool；与威吓联动时默认选中 +2。潜在增益进入池，明确联动才默认选中。

## 9. 威吓生效条件

问题：组合求值是否处理阻止威吓生效的特性？

决定：在当前引擎已支持的机制范围内，先判断威吓能否生效，再计算阶级。进攻方选中不服输和恒净之躯、防守方选中威吓时，默认阶级并集为 [+1, 0]。

## 10. 特性移除后的默认选择

问题：移除或更换特性后，是否撤回它产生的默认选择？

决定：未手动编辑的天气、场地与能力阶级 Track 根据当前特性重新计算默认选择；旧推荐值仍留在 Choice Pool。例如降雨换成无天气效果的特性后，未手动编辑的天气默认回到中性项。已经手动编辑的 Track 保留其选择。
