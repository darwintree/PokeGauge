# 效果等价 Scenario 来源展示讨论记录

对应 spec change: None.

## 1. 来源数据的保留粒度

问题：合并行是否必须保存每个原始 Scenario 的完整 Track 组合，还是可以按 Track 保留选项集合。

决定：当前范围内按 Track 保留选项集合；不保存完整组合列表。

## 2. 效果暂未支持的默认展示

问题：效果暂未支持的 Track 要素是否应在主行保持可见。

决定：与已判断未生效的要素一样默认折叠。

## 3. 折叠内容的组织方式

问题：展开后是否重复主行的生效要素，以及如何区分折叠状态。

决定：展开区只按 Track 展示折叠要素，不重复主行已展示的生效要素；已判断未生效与效果暂未支持使用不同状态标记。

## 4. 折叠入口规格

问题：是否提前规定折叠入口的数量、分类摘要或全局展开行为。

决定：不规定；按 YAGNI 留给实现采用最简单可用方式。

## 5. 效果等价键

问题：哪些信息参与判断两个 Scenario 是否效果等价。

决定：同一 Move snapshot 下，以实际送入伤害与概率计算的完整输入为等价键；UI 文案、来源选择和最终展示数字不参与。

## 6. 主行生效来源

问题：主行如何表达仍然生效的来源。

决定：直接按 Track 展示生效要素，不引入独立的来源领域组件。

## 7. 结果行布局

问题：行内来源、按生效机制分组与结果表加来源检查器三种方向采用哪一种。

决定：采用 A「行内来源」；每条结果行直接展示生效要素，并在同一行内提供默认折叠的其他已选项。
