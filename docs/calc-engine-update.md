# 计算引擎审计与更新

升级 calc 时，审计当前固定提交与目标提交之间的 delta，再同步更新支持名单。支持标记由本地名单驱动，不自动从引擎目录推断。规则约定见 [ADR 0009](adr/0009-champions-calc-engine.md)，当前版本和构建方法见 [vendor/README.md](../vendor/README.md)。

## 1. 审计上游差异

固定目标提交，查看旧提交到目标提交的差异，覆盖 `calc/src/mechanics/`、数据、共享工具以及相关测试。分别检查 Champions 和第九世代的影响，包括新增支持、行为修正和已有支持的回退。

对受影响的特性、道具、招式，确认实际执行路径及条件是否完整。增加名称、目录条目或部分实现，不足以判定支持；目录外内容有完整机制时也可支持。同时检查本地伤害展示、概率和连击逻辑是否需要同步调整。

在 `docs/research/YYYY-MM-DD-calc-delta-audit.md` 简要记录旧／新提交，以及每项受影响内容的规则、源码依据、支持结论和验证用例。可参考[首次支持审计](research/2026-09-14-champions-engine-support-audit.md)。

## 2. 更新实现与标记

按审计结论修改以下集中入口；确认支持后移出不支持名单，发现缺失或回退时加入名单。不要批量放开整个目录。

| 内容 | 支持判断入口 |
| --- | --- |
| 特性 | [`src/lib/ability/index.ts`](../src/lib/ability/index.ts) |
| 道具 | [`src/lib/held-item/support.ts`](../src/lib/held-item/support.ts) |
| 招式 | [`src/lib/move/rules-support.ts`](../src/lib/move/rules-support.ts) |

需要时同步修改引擎适配和本地效果逻辑。界面与计算共用支持判断：不支持的特性、道具保留选择但不应用效果；不支持的招式保留配置但使对应 Scenario 不可计算。切换规则后重新判断，不把支持状态写进书签或分享配置。

## 3. 更新依赖并验证

按 [构建说明](../vendor/README.md) 更新固定提交、重建包，更新依赖路径、锁文件和校验和；如数据有变化，同步更新资源生成适配并重新生成资源。

为受影响机制补充或调整行为测试，覆盖生效条件、边界及两种规则下的预期。验证实际伤害／概率和结果展示，避免仅测试名单成员关系。支持状态变化时，检查界面标记与计算效果一致，切换规则保留配置。

运行 `pnpm test`、`pnpm build` 和 `pnpm lint`。验证失败时先确认原因，再决定修正适配、保留不支持标记或暂缓升级。

## 4. 一起交付

将引擎版本、支持名单、必要的适配修改、测试和 delta 审计记录一起提交。用户可见的支持变化或计算修正按仓库约定添加多语言 changeset。

支持标记审计还应核对本地默认输入投影：特性通过天气、场地或阶级 Track 实现时，不能仅凭引擎没有直接处理该特性就标为未支持；同时，一次初始阶级推荐也不代表后续能力变化完整支持。参见[场地制造者标记审计](research/2026-09-15-support-marker-audit.md)。
